Serverless File Processing System

api gateway -> compute service -> storage -> security -> logging

-lambda have the upload, process & fetch functions
-s3 will store the file
-dynamodb will store the file's metadata
-gateway have endpoints get /files, post /upload, get /files/{id}
-Iam will assign the different roles

--- adding the decoupling and retry mechanism using the amazon sqs

-- need to create the message sender lambda function 
-- need to create the queue :  aws sqs create-queue `
>> --queue-name file-processing-queue `
>> --endpoint-url http://localhost:4566

--- need to create the event source mapping b/w the sqs and the lambda

aws lambda create-event-source-mapping `
>> --function-name Process-handler `
>> --event-source-arn arn:aws:sqs:ap-south-1:000000000000:file-processing-queue `
>> --endpoint-url http://localhost:4566

--- failure case will be handled by the sqs by retrying continuously to the respective event resource mapping 
--- Lambda service polls SQS based on the event source mapping and invokes the function when messages are available.
